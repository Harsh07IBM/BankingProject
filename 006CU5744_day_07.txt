Task 02:
Exception Testing

Java Code:

package Junit;

public class Day7_BankAccount {

    private String accountId;
    private double balance;

    public Day7_BankAccount(
            String accountId,
            double balance) {

        this.accountId = accountId;
        this.balance = balance;
    }

    public String getAccountId() {
        return accountId;
    }

    public double getBalance() {
        return balance;
    }

    public void deposit(double amount) {

        if (amount <= 0) {
            throw new IllegalArgumentException(
                    "Deposit amount must be positive"
            );
        }

        balance += amount;
    }

    public void withdraw(double amount) {

        if (amount > balance) {
            throw new IllegalArgumentException(
                    "Insufficient balance"
            );
        }

        balance -= amount;
    }
}

Java Code:

package Junit;

public class Day7_StringUtility {

    public static boolean isPalindrome(String text) {

        if (text == null) {
            return false;
        }

        String reversed =
                new StringBuilder(text)
                        .reverse()
                        .toString();

        return text.equalsIgnoreCase(reversed);
    }
}

Task 05:
What is JUnit Life Cycle Hook (Setup and Tear Down)?

JUnit Life Cycle Hooks are methods that run automatically at specific points during the execution of test cases.

The main lifecycle annotations are:

@BeforeEach

Runs before every test method.

@AfterEach

Runs after every test method.

@BeforeAll

Runs once before all test methods.

@AfterAll

Runs once after all test methods.

Setup means preparing the required environment before testing.

Tear down means cleaning up the resources after testing.

Task 07:
What are Assertions in JUnit 5?

Assertions are methods used to verify whether the actual result of a program matches the expected result.

If the assertion is correct, the test passes.

If the assertion is incorrect, the test fails.

Common JUnit 5 assertions are:

assertEquals()
assertNotEquals()
assertTrue()
assertFalse()
assertNull()
assertNotNull()
assertSame()
assertNotSame()
assertThrows()
assertDoesNotThrow()
assertTimeout()

Example:

assertEquals(10, calculator.add(5, 5));

Here:

Expected value = 10

Actual value = result of calculator.add(5, 5)

If both are equal, the test passes.

Task 08:
What is Time Test Performance Service?

Time-based testing is used to check whether a particular operation completes within a specified amount of time.

JUnit 5 provides assertTimeout() for this purpose.

For example, if we expect an operation to finish within 500 milliseconds, we can write:

assertTimeout(
        Duration.ofMillis(500),
        () -> service.performOperation()
);

If the operation takes longer than 500 milliseconds, the test fails.

Task 11:
JVM Architecture

JVM stands for Java Virtual Machine.

It is responsible for executing Java bytecode.

Basic JVM Architecture:

                 JVM
                  |
        -----------------------
        |                     |
   Class Loader          Runtime Data Areas
        |                     |
        |          ---------------------------
        |          |      |       |           |
        |       Method   Heap   Stack   PC Register
        |       Area
        |
   Bytecode
        |
   Execution Engine
        |
   -------------------------
   |           |           |
 Interpreter  JIT       Garbage
              Compiler   Collector
   |
   |
Native Method Interface
   |
Native Method Libraries
1. Class Loader

The Class Loader loads .class files containing Java bytecode into JVM memory.

2. Method Area

It stores class-level information, method information, static variables and runtime constant pool information.

3. Heap

The Heap is used to store objects and their instance data.

Garbage Collector works mainly on objects stored in the Heap.

4. Stack

Each thread has its own stack.

It stores local variables, method calls and stack frames.

5. PC Register

The Program Counter Register stores the address of the current JVM instruction being executed by a thread.

6. Execution Engine

The Execution Engine executes the bytecode.

It contains:

Interpreter
JIT Compiler
Garbage Collector
7. JNI

JNI stands for Java Native Interface.

It allows Java code to communicate with native code written in languages such as C and C++.

8. Native Method Libraries

These are native libraries required by the JVM to perform certain operations.

Task 12:
Why are Enums Useful?

Enums are useful when we have a fixed set of predefined values.

For example, in a banking application, an account can have a fixed set of statuses:

ACTIVE
BLOCKED
CLOSED

Instead of using normal strings:

String status = "ACTIVE";

we can use an enum:

AccountStatus status =
        AccountStatus.ACTIVE;

Advantages of Enums:

They provide type safety.
They prevent invalid values.
They make code more readable.
They represent fixed sets of constants.
They can be used with switch.
They can contain methods and constructors.
They make business logic easier to understand.

Task 13:
WAP to Show Importance of Enums in a Real-World Banking Application

package org.example;

enum AccountStatus {
    ACTIVE,
    BLOCKED,
    CLOSED
}

class CustomerAccount {

    private String accountNumber;
    private AccountStatus status;

    CustomerAccount(
            String accountNumber,
            AccountStatus status) {

        this.accountNumber = accountNumber;
        this.status = status;
    }

    public void displayStatus() {

        switch (status) {

            case ACTIVE:
                System.out.println(
                        accountNumber
                                + " account is active"
                );
                break;

            case BLOCKED:
                System.out.println(
                        accountNumber
                                + " account is blocked"
                );
                break;

            case CLOSED:
                System.out.println(
                        accountNumber
                                + " account is closed"
                );
                break;
        }
    }
}

public class Day7_BankingEnum {

    public static void main(String[] args) {

        CustomerAccount account =
                new CustomerAccount(
                        "ACC1001",
                        AccountStatus.ACTIVE
                );

        account.displayStatus();
    }
}

Output:

ACC1001 account is active

package org.example;

public class Day7_BankingStringMethods {

    public static void main(String[] args) {

        // 10. substring()

        // 11. indexOf()
        System.out.println(

                "Trimmed Name: "

                "Nominee Name Empty: "

                    "Valid Bank Account Number"

Add-on:
Nested Tests – Organized Scenarios

Nested tests are used to group related test cases inside another test class.

For example, bank account tests can be divided into:

Bank Account Tests
       |
       |---- Deposit Tests
       |
       |---- Withdraw Tests

JUnit 5 uses the @Nested annotation for this purpose.

package Junit;

import org.junit.jupiter.api.Nested;
import org.junit.jupiter.api.Test;

import static org.junit.jupiter.api.Assertions.*;

class Day7_NestedBankAccountTests {

    @Nested
    class DepositScenarios {

        @Test
        void testSuccessfulDeposit() {

            Day7_BankAccount account =
                    new Day7_BankAccount(
                            "ACC200",
                            500.0
                    );

            account.deposit(200.0);

            assertEquals(
                    700.0,
                    account.getBalance()
            );
        }

        @Test
        void testIncorrectDepositResult() {

            Day7_BankAccount account =
                    new Day7_BankAccount(
                            "ACC200",
                            500.0
                    );

            account.deposit(200.0);

            assertEquals(
                    800.0,
                    account.getBalance()
            );
        }
    }

    @Nested
    class WithdrawalScenarios {

        @Test
        void testSuccessfulWithdrawal() {

            Day7_BankAccount account =
                    new Day7_BankAccount(
                            "ACC200",
                            500.0
                    );

            account.withdraw(100.0);

            assertEquals(
                    400.0,
                    account.getBalance()
            );
        }

        @Test
        void testIncorrectWithdrawalResult() {

            Day7_BankAccount account =
                    new Day7_BankAccount(
                            "ACC200",
                            500.0
                    );

            account.withdraw(100.0);

            assertEquals(
                    300.0,
                    account.getBalance()
            );
        }
    }
}
