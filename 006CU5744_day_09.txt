Task 9: How many types of IoC are there in Spring?

In Spring, IoC is mainly achieved through two types of Dependency Injection:

1. Constructor Injection

The dependency is provided through the class constructor.

class Car {
    private Engine engine;

    Car(Engine engine) {
        this.engine = engine;
    }
}

Spring provides the Engine object through the constructor.

2. Setter Injection

The dependency is provided through a setter method.

class Car {
    private Engine engine;

    public void setEngine(Engine engine) {
        this.engine = engine;
    }
}

Spring provides the Engine object using the setEngine() method.

Note: IoC is a broad concept, and DI is one of the main ways Spring implements IoC.

Task 10: What is DI in Spring?

DI stands for Dependency Injection.

Dependency Injection means Spring provides the required dependency (object) to a class instead of the class creating the object itself.

Example:

class Car {
    private Engine engine;

    Car(Engine engine) {
        this.engine = engine;
    }
}

Here, Car needs an Engine. Instead of creating Engine inside Car, the Engine object is provided from outside.

In simple words:
DI = Spring gives the required object to our class.

Task 13: What are the different ways to configure Spring applications?

Task 16: What is Bean Scope? Give different scopes with description.

Bean Scope defines how long a Spring Bean will live and how many objects of that Bean Spring will create.

Spring provides several Bean scopes:

1. Singleton

Only one object of the Bean is created per Spring IoC Container.

@Scope("singleton")

This is the default scope in Spring.

2. Prototype

A new object is created every time we request the Bean from the Spring Container.

@Scope("prototype")
3. Request

A new Bean object is created for each HTTP request.

@Scope("request")

Mainly used in web applications.

4. Session

A Bean object is created for each HTTP session.

@Scope("session")

It remains available throughout that user's session.

5. Application

A Bean object is created for the lifetime of the web application.

@Scope("application")
6. WebSocket

A Bean object is created for the lifetime of a WebSocket session.

@Scope("websocket")
Quick Summary:
Singleton  → One object per Spring Container
Prototype  → New object every time requested
Request    → One object per HTTP request
Session    → One object per HTTP session
Application → One object per web application
WebSocket  → One object per WebSocket session
Task 17: What is Autowiring in Spring?

Autowiring means Spring automatically finds and injects the required dependency into a Bean.

For example, suppose Car needs an Engine.

@Component
class Engine {
}
@Component
class Car {

    @Autowired
    private Engine engine;
}

Here, Spring automatically finds the Engine Bean and injects it into Car.

In simple words:

Autowiring means Spring automatically connects the required objects for us.

Task 18: What are the different ways of Autowiring?

There are mainly 3 common ways of autowiring in modern Spring:

1. Constructor Autowiring

Dependency is injected through the constructor.

@Component
class Car {

    private Engine engine;

    @Autowired
    public Car(Engine engine) {
        this.engine = engine;
    }
}

If there is only one constructor, @Autowired can usually be omitted.

Recommended approach because dependencies are clear and can be made final.

2. Setter Autowiring

Dependency is injected through a setter method.

@Component
class Car {

    private Engine engine;

    @Autowired
    public void setEngine(Engine engine) {
        this.engine = engine;
    }
}

Useful when the dependency is optional or can be changed.

3. Field Autowiring

Dependency is injected directly into a field.

@Component
class Car {

    @Autowired
    private Engine engine;
}

It is simple to write, but constructor injection is generally preferred in modern Spring applications.

Quick Summary:
Autowiring
    |
    |--- Constructor Injection
    |
    |--- Setter Injection
    |
    |--- Field Injection

Task 20: Difference between @Component and @Bean

Both are used to create Spring Beans, but they are used differently.

@Component

We put @Component directly on the class.

@Component
class Engine {
}

Spring automatically finds this class during component scanning and creates a Bean.

@Bean

We put @Bean on a method inside a configuration class.

@Configuration
class AppConfig {

    @Bean
    public Engine engine() {
        return new Engine();
    }
}

The object returned by the method becomes a Spring Bean.

Main Difference:
@Component	@Bean
Used on a class.	                        Used on a method.
Spring automatically discovers the class.	We explicitly create and return the object.
Good for classes that we own.	           Useful for third-party classes or custom object creation.

In simple words:

@Component → "Spring, please manage this class."
@Bean → "Spring, please manage the object returned by this method."

Task 30: Internal working of the given Spring Boot code

Given code:

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class MyApplication {

    public static void main(String[] args) {
        SpringApplication.run(MyApplication.class, args);
    }
}
Step 1: Program starts

Java starts execution from the main() method:

public static void main(String[] args)
Step 2: SpringApplication.run() is called
SpringApplication.run(MyApplication.class, args);

This starts the Spring Boot application.

It receives:

MyApplication.class → Main configuration class
args                → Command-line arguments
Step 3: Spring Boot creates the ApplicationContext

Spring Boot creates an ApplicationContext.

The ApplicationContext is responsible for managing Spring objects called Beans.

Step 4: @SpringBootApplication is processed

This annotation is very important.

@SpringBootApplication

It is a combination of three annotations:

@SpringBootConfiguration
@EnableAutoConfiguration
@ComponentScan
Step 5: Component Scanning

@ComponentScan tells Spring to search for classes such as:

@Component
@Service
@Repository
@Controller

Spring finds these classes and creates their objects as Spring Beans.

Step 6: Auto-Configuration

@EnableAutoConfiguration tells Spring Boot to automatically configure the application based on the dependencies available in the project.

For example, if we add the Web starter:

spring-boot-starter-web

Spring Boot automatically configures many things required for web development.

Step 7: Dependency Injection

Spring creates and manages the required Beans and injects dependencies where needed.

For example:

Controller
    ↓
Service
    ↓
Repository

Spring connects these objects using Dependency Injection.

Step 8: Embedded Server starts

If we have a web application and the required web dependency is present, Spring Boot starts an embedded server such as Tomcat.

Spring Boot Application
        ↓
Embedded Tomcat
        ↓
Application starts
Step 9: Application is ready

After all configuration, Bean creation, dependency injection, and server startup are completed, the application becomes ready to receive requests.
