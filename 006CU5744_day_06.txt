Task 4:
Create an interface with one abstract method and one normal method.

A Functional Interface can have only one abstract method.

It can have multiple default and static methods.

Yes, an abstract method can be explicitly written using the abstract keyword.

We cannot have two abstract methods in a Functional Interface.

package org.example;

@FunctionalInterface
interface Action {

    abstract void perform(int value);

    default void showMessage() {
        System.out.println("Welcome to Java");
    }

    default void displayInfo() {
        System.out.println("This is another default method");
    }

    static void showStaticMessage() {
        System.out.println("This is a static method");
    }
}

public class Day6_FunctionalInterface {

    public static void main(String[] args) {

        Action action =
                value -> System.out.println(
                        "Result: " + (value * 2)
                );

        action.perform(50);

        action.showMessage();

        action.displayInfo();

        Action.showStaticMessage();
    }
}

Output:

Result: 100
Welcome to Java
This is another default method
This is a static method

Note:

A Functional Interface can have:

Only one abstract method.
Multiple default methods.
Multiple static methods.
Methods inherited from Object do not count as abstract methods for this purpose.

A JUnit Test Suite is a collection of multiple test classes that can be executed together.

In JUnit 5, test suites can be created using the JUnit Platform Suite support.

Task 11:
What is JUnit Vintage?

JUnit Vintage is a test engine provided by JUnit 5.

It allows older tests written using JUnit 3 and JUnit 4 to run on the JUnit 5 platform.

It is useful when a project is migrating from an older JUnit version to JUnit 5 and still has old tests.

Task 12:
What are Mock Objects?

Mock objects are fake objects used during testing.

They are used to simulate the behavior of real objects or external dependencies.

For example, suppose our application gets data from a database. During testing, instead of connecting to the actual database, we can use a mock object to provide fake data.

Mock objects help us:

Test individual components separately.
Avoid depending on external systems.
Make tests faster.
Control the behavior of dependencies.
Test different situations easily.

Task 13:
Write about Mockito

Mockito is a popular mocking framework used with Java unit testing.

It is commonly used with JUnit to create mock objects.

Mockito allows us to:

Create mock objects.
Define the behavior of mock objects.
Verify whether a method was called.
Test classes independently.
Avoid using real external dependencies during unit testing.

Example:

UserService service = mock(UserService.class);

when(service.getUserName())
        .thenReturn("Harsh");

System.out.println(
        service.getUserName()
);

Here, Mockito creates a fake UserService object and returns "Harsh" when getUserName() is called.

Define Functional Interface – A Java 8 Feature

A Functional Interface is an interface that contains exactly one abstract method.

It can have multiple default and static methods.

The @FunctionalInterface annotation is used to tell the compiler that the interface should contain only one abstract method.

Example:

@FunctionalInterface
interface Calculator {

}

Functional Interfaces are mainly used with Lambda Expressions.

Some built-in Functional Interfaces are:

Predicate
Function
Consumer
Supplier

Task 15:
What are Default and Static Methods in Interfaces?

Default Method

A default method is a method inside an interface that has a method body.

It is declared using the default keyword.

interface Demo {

    default void show() {
        System.out.println("Default Method");
    }
}

A class implementing the interface can directly use the default method or override it.

Static Method

A static method belongs to the interface itself.

It is called using the interface name.

interface Demo {

    static void display() {
        System.out.println("Static Method");
    }
}

It is called like:

Demo.display();

Java 8 Stream API

The Stream API is used to process collections of data in a simple and efficient way.

package org.example;

import java.util.ArrayList;
import java.util.List;
import java.util.stream.Collectors;

public class Day6_StreamAPI {

    public static void main(String[] args) {

        List<String> names = new ArrayList<>();

        names.add("Harsh");
        names.add("Ravi");
        names.add("Sam");
        names.add("Aman");

        List<String> result = names.stream()
                .filter(name -> name.startsWith("S"))
                .collect(Collectors.toList());

        System.out.println(result);
    }
}

Output:

[Sam]

Task 17:
What is Optional Class in Java 8?

Optional is a class introduced in Java 8.

It is used to represent a value that may or may not be present.

It helps reduce the chances of NullPointerException.

Example:

Optional<String> name =
        Optional.ofNullable(null);

We can provide a default value using:

String result = name.orElse("Guest");

If the value is not available, "Guest" will be returned.

Task 18:
What is the error in the below Optional class?

Given code:

Optional.ofNullable(user)
        .map(User::getName)
        .orElse("Guest"); [1];

There are errors in this code.

User class is not defined.
User::getName is being used, but user is declared as a String.
String user = "Prasunamba";

A String does not have a getName() method.

[1] is invalid Java syntax.

package org.example;

    }

Task 19:
What is the double colon :: operator?

The :: operator is called the Method Reference Operator.

It is used to refer to an existing method without calling it directly.

Example:

System.out::println

Instead of:

x -> System.out.println(x)

Method references are commonly used with Lambda Expressions and Functional Interfaces.

Task 20:
What is Method Reference in Java 8?

Method Reference is a feature introduced in Java 8.

It provides a shorter way to write Lambda Expressions when an existing method can be directly used.

Syntax:

ClassName::methodName

Example:

numbers.forEach(System.out::println);

This is similar to:

numbers.forEach(number ->
        System.out.println(number));

What are GOD Classes?

A God Class is a class that tries to do too many things in a software application.

It usually contains too much business logic and has too many responsibilities.

For example, one class might handle:

User registration
Login
Database operations
Payment processing
Email sending
Report generation

This makes the class very large and difficult to understand and maintain.

Problems with God Classes:
Difficult to maintain.
Difficult to test.
Difficult to understand.
Changes in one functionality can affect other functionalities.
Violates the Single Responsibility Principle.
Simple Example:
God Class
   |
   |--- User Management
   |--- Database
   |--- Payment
   |--- Email
   |--- Reports

Instead, responsibilities should be separated into different classes:

UserService
PaymentService
EmailService
ReportService
DatabaseService

This makes the application cleaner, easier to maintain and easier to test.
