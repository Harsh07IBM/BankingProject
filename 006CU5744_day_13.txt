Task 2: What do you understand by Indexing in DBMS? How does it work?
Answer:

Indexing is a technique used in DBMS to speed up data retrieval. It creates a separate data structure (called an index) that stores column values along with pointers to the actual rows.

Without an index, the database checks every row (Full Table Scan).
With an index, the database directly finds the required row, making searches much faster.

Small Example:

Suppose we have an Employee table:

| Emp_ID | Name  | Salary |
| -----: | ----- | -----: |
|    101 | Rahul |  50000 |
|    102 | Priya |  60000 |
|    103 | Aman  |  55000 |

If we create an index on Emp_ID, searching for Emp_ID = 102 becomes very fast because the database directly jumps to that record instead of checking every row.

Task 3: Do you think Indexing strategy improves query performance? Explain.
Answer:

Yes, Indexing improves query performance because it helps the database find records quickly without scanning the entire table.

An index works like the index of a book. Instead of reading every page, you directly go to the required page using the index.

Small Example:

If an Employee table has 1,00,000 records and you search for:

SELECT * FROM Employee WHERE Emp_ID = 1050;
Without Index: Database checks all rows (Full Table Scan).
With Index: Database directly finds the required row.

Advantages:

Faster SELECT queries.
Improves search, sorting, and join performance.

Disadvantage:

Takes extra storage.
Slows down INSERT, UPDATE, and DELETE because the index must also be updated.
Task 4: What are the ACID Properties in RDBMS? Explain.
Answer:

ACID properties ensure that every database transaction is safe, accurate, and reliable.

| Property            | Meaning                                                                              | Example                                                                                         |
| ------------------- | ------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------- |
| **A - Atomicity**   | A transaction is completed fully or not at all.                                      | If money is deducted from Account A but not added to Account B, the transaction is rolled back. |
| **C - Consistency** | The database remains in a valid state before and after the transaction.              | Bank balance rules are always maintained after a transaction.                                   |
| **I - Isolation**   | Multiple transactions do not interfere with each other.                              | Two users withdrawing money at the same time do not affect each other's transactions.           |
| **D - Durability**  | Once a transaction is committed, it is permanently saved even if the system crashes. | After a successful payment, the transaction remains saved even after a power failure.           |

Small Example: Bank Transfer

Suppose ₹1000 is transferred from Account A to Account B.

Atomicity: Both debit and credit happen together; otherwise, rollback.
Consistency: Total money in the bank remains the same.
Isolation: Other users cannot see the transaction until it is completed.
Durability: Once the transfer is successful, it remains saved permanently, even if the server crashes.
